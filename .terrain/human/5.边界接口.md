# 5. 边界接口

**生成日期**：2026-09-13

---

## 概述

边界接口指 Litho 整个系统与外部世界打交道的"表面"。它包含三个层面：**对外入口**——CLI 参数与 `main.rs` 的调度，用户在那里下达任务；**过程接口**——运行中与 Git、Mermaid 修复器等外部可执行程序的关系；**集成边界**——`integrations/` 对本地知识文档的摄取能力。换句话说，这里回答三个问题：用户怎么使唤它？它靠哪些外部程序完成闭环？它可以从哪些外部资料里"偷师"？

## CLI 入口

| 命令 | 说明 | 出处 |
|------|------|------|
| `litho`（默认） | 读取 `litho.config.toml`，执行完整文档生成流水线 | `src/cli.rs` / `src/main.rs` |
| `litho sync-knowledge` | 强制或按需同步外部本地知识缓存 | `src/main.rs` 的 `SyncKnowledge` 分支 |

**核心流程说明**：`main.rs` 无子命令时调用 `launch(&config)`（`src/main.rs`），`generator::workflow::launch`（`src/generator/workflow.rs:45`）依序驱动预处理/研究/撰写/输出四阶段。`TargetLanguage`、`output_path`、各阶段 skip 开关等均由 CLI 解析纳入 `Config` 后注入（`src/cli.rs` → `src/config.rs`）。

## 配置接口

| 配置项 | 用途 | 出处 |
|------|------|------|
| `target_language`（如 `zh`） | 决定文档语言、文件名与提示词语言 | `src/config.rs` / `src/i18n.rs:5` |
| `llm_provider`、`api_key`、`model_efficient`/`model_powerful` | LLM 厂商与双模型选择 | `src/config.rs` / `src/llm/client/providers.rs:24` |
| `output_path` | 输出目录（默认 `./litho.docs`） | `src/config.rs` / `src/generator/outlet/mod.rs:78` |
| `cache_options` | 缓存开关与目录 | `src/config.rs` / `src/cache/mod.rs` |
| `memory_options` | 内存相关开关 | `src/config.rs` / `src/generator/context.rs` |
| `preprocessing.skip_*` 等 | 各阶段跳过开关（`--skip-*`） | `src/config.rs` / `src/generator/workflow.rs:106-166` |
| `knowledge.local_docs` | 本地知识文档的同步配置（分类/路径/分块） | `src/config.rs` / `src/integrations/knowledge_sync.rs` |

## 外部程序/进程依赖

| 外部程序 | 用途 | 调用形式 |
|---------|------|---------|
| Git | `git_tracked_only` 扫描只跟踪已提交文件，代码层直接调用 git 逻辑 | `src/generator/preprocess/extractors/structure_extractor.rs` / `src/utils` |
| `mermaid-fixer` | 输出后修复 Mermaid 图，启动时预检可用性 | `src/generator/outlet/fixer.rs` / `src/generator/workflow.rs:73-75` |

## 集成边界

内部模块间的接口以「内存作用域 + 键」约定为主：

| 接口 | 说明 | 出处 |
|------|------|------|
| `store_to_memory` / `get_from_memory` | 阶段间数据交接通道（preprocess/studies_research/documentation/timing） | `src/generator/context.rs` |
| `DocTree` | 文档类型→文件名映射，输出侧唯一入口 | `src/generator/outlet/mod.rs:19` |
| `get_doc_filename` | 8 语言下文档文件名的单一事实来源 | `src/i18n.rs:147` |

**集成建议**：若要在外部系统中复用 Litho 的研究结论，可直接读取 `studies_research` 作用域内对应键的报告；若要按语言组织沉淀，可通过 `TargetLanguage::Chinese → get_doc_filename` 得到与 Litho 一致的文件名。

对应深探文档：`4.Deep-Exploration/核心生成编排领域.md`、`4.Deep-Exploration/输出领域.md`、`4.Deep-Exploration/国际化领域.md`。
